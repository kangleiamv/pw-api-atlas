02 / Request model

Authentication, as documented

The app uses bearer tokens and a set of application headers. The request console forwards only what you enter; the optional OTP helper uses fixed login operations with app constants applied server-side. This explorer does not bundle a token, fabricate a session, or bypass authentication.

Manual helper / Your account only

Send an OTP and exchange it for a bearer token

Idle

This optional helper asks the local server to send an OTP to a number you control and then exchange that OTP for an access token. It uses only the documented get-otp-app and oauth/token operations. The server applies the app’s OAuth client identifiers, enforces a cooldown and attempt limit, and returns a redacted result. Nothing is written to disk or browser storage, and the phone number, OTP and token are never logged.

Access token masked until revealed · kept in page memory only

The account-deletion OTP routes (/v3/otp-app and /v3/otp/verify) are deliberately not used. Sign-in is disabled until the authorized-use notice above is accepted. Do not paste a token from someone else, and stop if the account shows a device or session warning you do not recognize.

Bearer token

The recovered interceptor reads a token from the app’s auth provider and sends it as Authorization: Bearer <token>. Token endpoints are the documented entry points. Operations not marked public require a token in the console; operations flagged public can be called without one. You can paste a token below or obtain one for your own account with the manual OTP helper above.

The request console keeps a token in page memory for the life of the tab. It is never written to storage, placed in a URL, or logged by the local server.

Application headers

These identifiers were found in the APK and are documented for research. The generic request console does not add them automatically. The optional OTP helper applies the required subset server-side to match the app; elsewhere you can add them explicitly when your authorized test requires them.

04 / Method

Recovered, merged, left unverified

The catalog is the product of static analysis. It is evidence of what the package declares, not a claim that every endpoint works or is reachable in production.

  1. 01

    Unpack

    The APKS was split into its base APK, then all 18 DEX files were extracted.

  2. 02

    Read annotations

    Ktorfit and Retrofit interface annotations supplied verbs, paths, headers and parameter bindings.

  3. 03

    Resolve names

    R8-renamed Retrofit annotations were mapped from RequestFactory$Builder bytecode.

  4. 04

    Merge, do not invent

    Duplicate declarations became one operation; every original declaration is retained in the entry.

Known limits

  • No operation was called against production during extraction.
  • DTO fields were not reconstructed; types are named, not expanded.
  • Runtime @Url operations and external URLs stay outside OpenAPI.
  • Free-form maps cannot be described statically.
  • Gateway routing, feature flags and server validation may differ.
